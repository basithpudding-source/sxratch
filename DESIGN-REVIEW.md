# SXRATCH / PAD — Full Design & Functionality Review

> Historical review: this document records the section-based PAD implementation
> reviewed in July 2026. The live app now uses `js/daw.js`; the retired Song Builder
> and its sampled-instrument asset chain were removed on 2026-08-08. See `README.md`
> and `ARCHITECTURE.md` for the current product.

Reviewed: entire codebase (index.html, app.js, audio-engine.js, input.js, waveform*, songbuilder.js, practice.js, all three stylesheets, PWA/SW/build/server). Date: 2026-07-15.

**Verdict in one line:** the audio engine and interaction code are genuinely excellent (worklet scratch engine, SAB jog channel, coalesced pointers, offline rendering, undo/autosave). What holds the product back from feeling premium is the *presentation layer*: three overlapping layout generations, decorative fake data on a real instrument, an invisible "active deck" model, fragmented brand tokens, and touch targets/mobile ergonomics that don't match the engineering quality underneath.

---

## 1. Cross-cutting problems (fix these first — they gate everything else)

### 1.1 Fake instrumentation breaks trust (P0)
A premium instrument never lies. Right now the deck skin paints several things that look live but aren't:

- **BPM readout is hard-coded `124.0`** and **key is hard-coded `7A`/`8A`** (`app.js` `composeDeckConsole`, `.track-bpm` / `.track-key` never updated) — yet `deck.bpm` exists and SYNC uses it.
- **Two red playheads**: `decks.css` paints a decorative playhead at `left: 46%` of `.wave-stage`, while the real canvas playhead is at 50%. Visibly wrong whenever a track is loaded.
- **Fake waveform texture** (`.wave-lane::before` clip-path polygon) renders *behind the real waveform canvas* and shows through its transparent background — a static decorative wave under a live one.
- **Fake bar numbers** ("17 18 19 20") in `makeWaveGrid`, fake "Bars" label.
- **Topbar master VU** is a static gradient; **master volume "knob"** is a 34×34 invisible `<input type=range>` under a painted knob — nearly unusable and not rotatable.
- **`DECK A ▼` chevron** implies a menu that doesn't exist; **album-art tiles** are permanent placeholder gradients.

**Recommendation:** wire or remove every one of these.
- Show live BPM: `deck.bpm × (1 + tempo/100)`, updated on tempo/sync/load; add lightweight BPM detection on load (onset-envelope autocorrelation, ~60 lines, run in a worker) so real files get real numbers. Until detected, show `--`.
- Remove the key display (or implement a chromagram Camelot estimate later — don't fake it).
- Delete the 46% pseudo-playhead and the clip-path fake wave; draw real bar/beat ticks in `waveform-draw.js` from BPM + a downbeat anchor.
- Make the master control a real knob (reuse `attachKnob` + arc), and drive the topbar VU from the master analyser (peak-hold segments).
- Use the album-art tile for something true: rendered mini-waveform thumbnail, or PAD-song badge when the deck holds a PAD render.

### 1.2 Three layout systems coexist (P0 for maintainability)
`styles.css` still ships the legacy flex bands **and** the "Phase 2 OMNIS" grid (`use-landscape-layout`, ~300 lines), while `composeDeckConsole()` + `decks.css` rebuild everything into the `.controller-shell` skin that actually renders — via heavy `!important` overrides. Confirmed dead: `#stack-btn`/`body.stack-view` (button hidden; `.decks-top` no longer exists), `#rotate-hint` markup, `.fx-row`/`.beatfx` styles, most of the Phase-2 grid.

**Recommendation:** commit to the controller shell. Move its markup into `index.html` (or a template) instead of runtime DOM surgery, delete the Phase-2 grid + stack-view + rotate-hint + legacy band CSS, and collapse `styles.css`/`decks.css` overlap. Expected: ~35–40% less CSS, no `!important` wars, and the mobile media queries become tractable. Keep `composeDeckConsole` only if you want progressive enhancement without JS — you don't (app is JS-only).

### 1.3 The invisible "active deck" model (P0 UX)
After the recompose, LINK / DBL / Presets / Zoom and the entire **loop strip exist only once**, retargeted to the "active deck" — but the only cue is `.deck-side.active` with an inset shadow at 2.5% alpha (imperceptible) and a border tint on the toolbar. Users will zoom/loop/load the wrong deck constantly, and Deck B appears to have lost its loop controls.

**Recommendation:** add an explicit, always-visible **A | B segmented toggle** at the left of the wave toolbar and loop strip (colored teal/pink), plus a strong active treatment on the deck side (2px inner border in deck color + heading glow). Bonus: auto-follow the last-touched deck (current behavior) but flash the toggle when it switches so the change is noticed.

### 1.4 Design tokens & brand are fragmented (P1)
Three unreconciled palettes: `styles.css` (`--accent-a #37e6c8`, `--accent-b #ff5d8f`, brand green `#3ddc84` / red `#ff4d4d`), `decks.css` (`--deck-a #48ddd3`, `--deck-b #ff6175`), `studio.css` (`--pad-amber #ffbd3d` family). The start overlay brands SXRATCH **green** and PAD **red** — colors that appear nowhere in the actual product. Radii range 2/4/6/7/8/9/10/14px ad hoc; `font-family` is declared as Inter but **no webfont is ever loaded** (silently falls back to system), while decks/studio use `system-ui` shorthands with weights 850/950.

**Recommendation:** one `tokens.css`:
- Brand: **SXRATCH = teal `#48ddd3`, PAD = amber `#ffbd3d`**, Deck B pink as *deck* color only. Restyle the start overlay and nav to match (kill green/red). The icon.svg (teal ring / pink label) already agrees.
- Type: self-host a variable font (offline PWA ⇒ no Google CDN): e.g. **Inter Variable** for UI + **JetBrains Mono / IBM Plex Mono** for all numeric readouts (BPM, time, tempo %) with `font-variant-numeric: tabular-nums`. Define 5 text styles (display/label/body/readout/micro) and stop using 0.46–0.58rem sizes — floor at 10px.
- Space/radius/elevation scales: 4-pt spacing; radii 4 (controls) / 8 (cards) / 12 (shell); 3 shadow levels with one light direction (top). Both DJ skin and PAD consume the same tokens so the two modes feel like one product.

### 1.5 Accessibility ≈ premium (P1)
- Knobs, faders, jog pads and sampler pads are `div`s: no `role="slider"`/`button`, no `aria-valuemin/max`, no keyboard operation, no focus ring (only `.controller-shell button:focus-visible` exists). Add roles + arrow-key nudging to `attachKnob`/`attachFader` (they already have `set()` — trivial), make sampler pads `<button>`s.
- Dialogs: no focus trap, no `Esc` close, no `aria-modal`. Convert to `<dialog>` or add both.
- `user-scalable=no` + tiny text harms low-vision users; keep pinch disabled only on the performance surfaces via `touch-action` (already done) and drop `maximum-scale`.
- Contrast: `--deck-dim #6c7b86` labels on `#0b151d` ≈ 3.4:1 at 8–9px — fails. Bump to ≥ #93a5b4 at ≥10px.
- `prefers-reduced-motion` is honored only inside `.controller-shell`; extend to coach pulse, REC pulse, pad pulses, PAD glows.

## 2. SXRATCH (deck view) — desktop

**What's already strong:** the hardware-shell aesthetic, per-deck FX strips, real knob arcs/tick scales, double-click-to-neutral, remappable everything, SAB-backed scratch latency, practice coach highlighting real controls.

Recommended changes, in priority order:

1. **Waveform stage upgrade** (biggest visual lever). Current: 1px-stroke min/max peaks, single color, fixed 4000 peaks (zoom just stretches → blocky). Move to: filled symmetric waveform with two-band tint (lows in deck color, highs white overlay — compute a second "high-band" peak array once at load), beat/bar ticks from BPM grid, downbeat numbers replacing the fake 17–20, loop region tinted in deck color (not indigo), cue flags with letters and a small kill-zone hover state, and multi-resolution peaks (re-peak at >4× zoom). Keep the worker path.
2. **Drawer redesign.** `🎛 Pads/FX` currently *covers the mixer* with a modal overlay — you cannot crossfade or EQ while sampling, which is exactly when you need to. Dock the sampler + FX as a bottom strip that compresses the center column instead of occluding it (the grid already supports an extra row), keep crossfader always visible. Rename button to `SAMPLER · FX`.
3. **Make BOTH/master survive small heights.** At `max-height:560px` the BOTH button, master and help are `display:none`. Fold them into the wave toolbar instead of deleting: Space already plays both, but touch users lose the feature entirely.
4. **Transport truthfulness:** buttons were relabeled `● START / ◀◀ REW / ▶▶ FF` by JS while the Help dialog and README still describe `⏮ ⏪ ⏩`; reconcile. Add press-state depth (translateY 1px + shadow collapse) for hardware feel.
5. **Micro-interactions** (cheap, high perceived value): needle-drop ripple on waveform click; platter ring glow while `.touching`; VU peak-hold caps; crossfader center détente tick (snap ±0.02 with a haptic pulse on mobile); REC button count-up already good — add a red frame pulse around the whole shell while recording.
6. **Recorder output:** produces `.webm` despite README's "WAV". You already have `bufferToWav` — decode the webm blob and offer "Save WAV" alongside webm. Show an ARIA-live "REC 1:42" for screen readers.
7. **Empty states:** decks start silent with "No track loaded". Offer a one-tap **DEMO** chip on each empty waveform (loads the synth presets) so first-run users reach sound in <5 seconds.
8. **Hidden-feature surfacing:** trackpad Ctrl-scratch, slam, hamster mode, MIDI learn are invisible. Add a dismissible 3-step coach-mark tour after first "Enter the booth" (you already have the coach/highlight infrastructure in practice.js — reuse it), and a `?`-key shortcut overlay that labels every control with its binding (generated from `config.keys`, so it's always true).

## 3. Mobile (both areas)

1. **Portrait strategy (P0).** `body.ui-rotated` fakes landscape by rotating the whole body 90° with fixed positioning. Input handlers compensate, but native widgets (selects, range sliders, file pickers, the URL dialog keyboard) render rotated, scroll behaves oddly, and `visualViewport` math fights it. Options, in order of preference: (a) design a real portrait layout — stacked decks with one shared platter area and swipeable A/B, (b) keep the rotate *prompt* (you built one, then disabled it with `display:none !important`) and drop the transform hack, (c) TWA already locks landscape via manifest — align web behavior with it. The CSS-rotation path will keep generating bugs.
2. **Touch targets (P0).** `pointer:coarse` only bumps `.btn` padding and knobs to 44px. At small heights you ship 22–30px knobs, 24px toolbar buttons, 25px hotcue chips, 0.5rem loop labels. Enforce ≥44px hit areas everywhere via an inset `::after` hit-expander even where visuals stay compact; drop non-essential chrome (tick labels) before shrinking interactive elements.
3. **Layout budget on phones:** at `max-height:560px` you currently hide hot cues, SET/START/REW/FF, BOTH, master, help — i.e., the product's depth disappears. Prefer progressive disclosure (swipe-up second row, or per-deck "more" sheet) over deletion.
4. **PAD on phones:** portrait shows a blocking "rotate" card (good). Landscape-phone PAD is genuinely usable, but: mode tabs at 28px height with 0.54rem text are below target; the utility cluster (`Export/Import/Undo/Redo` and the **engine selector**) is `display:none !important` — undo exists only as Ctrl+Z, which phones don't have. Add Undo/Redo to the keyboard-dock actions on small screens.
5. **iOS specifics:** add `-webkit-tap-highlight-color: transparent`, verify AudioContext resume on `visibilitychange` (backgrounded Safari suspends; currently only `pagehide` flushes saves), and gate haptics copy (`navigator.vibrate` is Android-only — the settings row already says "unsupported here", good).
6. **Viewport heights:** unify on `100dvh` + a `--topbar-h` custom property. Today `#studio` uses `calc(100dvh - 47px)` while the topbar is actually 60/50/42px depending on media query — PAD is off by 13px on desktop (masked by `overflow:hidden`, but it clips the inspector).

## 4. PAD (song builder)

**What's already strong:** section/lane model, chord recognition with slash/inversion naming, shared 88-key dock with per-lane focus, per-track mix+FX with solo/mute, LRU render cache, JSON import/export, debounced autosave + pagehide flush, undo/redo.

1. **Perf: stop full re-renders (P0 on mobile).** Nearly every interaction calls `renderEditor()` which rebuilds the whole editor *including the 88-key keyboard DOM* (~250 nodes). On a phone this is visible jank per note. You already have targeted refreshers (`refreshChords`, `refreshSharedKeyboard`) — extend that pattern: per-lane grid patching (toggle classes on existing cells) and never rebuild the keybed (only re-class keys).
2. **Timing feel:** add **swing** (global + per-section, applied in `renderSectionInto` by offsetting odd steps) and **per-step velocity/accent** (tap-and-hold or second tap cycles normal→accent→ghost). These two features are the difference between "toy sequencer" and "instrument", and both are pure scheduling math you already control.
3. **Musical workflow gaps:** metronome + 1-bar count-in for section play; tap-tempo on the BPM module; per-section BPM (structure supports it — `secPerQuarter` is global-only); chord audition on hover; a "humanize" ±ms option.
4. **MIDI into PAD:** `midi.js` routes notes 36–43 to sampler pads globally. When `view-studio` is active, route MIDI notes to the shared keyboard's current lane (chords: chord entry; bass/lead: step write; drums: hits). This is a marquee premium feature and the plumbing exists.
5. **Projects, not one slot:** `sxratch.song` is a single autosave. Add named project slots (list in a dialog, stored as `sxratch.songs.{id}`, with "duplicate" and relative-time stamps). Losing a song by starting a new one is the current default outcome.
6. **Render-cache memory:** LRU caps at 4 *buffers*; a 4-minute stereo render ≈ 40–80MB each. Cap by total seconds (e.g. 10 min) instead of count.
7. **Destructive-action safety:** "Delete section", "Clear lane/kit" act instantly. They're undoable — say so: toast "Section deleted — Undo" with an inline undo button; keep confirm-free (premium = reversible, not nagging). Sampler pad `dblclick` clear also fires the sample twice first (two `click`s precede `dblclick`) — require long-press or the ⚙ route instead.
8. **Inspector honesty (same principle as §1.1):** `.inspector-wave` is a fake static bar row — replace with a rendered mini-waveform of the last section render, or lane-activity sparkline (you already compute densities). Remove `.rail-faders` decorative fader graphics if unused.
9. **Sampler lane resilience:** placements persist but buffers don't (rows show ⚠ after reload). Offer "re-import pads" CTA directly on the ⚠ row, and consider persisting small slices (< a few MB) to IndexedDB — pad slices from loops are tiny and would make reloads seamless.
10. **Export MIDI** (chords/bass/lead/drums → .mid) — cheap to implement, huge perceived pro value alongside WAV/JSON.
11. **Send-to-deck loop closure:** after "→ Deck A", you toast and stay in PAD; actually switching happens via `_onUse`. Good — but set the deck BPM to `song.bpm` on send (it currently stays 120 ⇒ auto-loop/sync are wrong on your own composition!) and drop a hot cue at each section boundary. That turns PAD→SXRATCH into the killer workflow it's meant to be.

## 5. Smaller correctness/quality items

- `ui.setPlaying` sets `textContent` then immediately overwrites with `innerHTML` — dead line.
- `attachFader` wipes and rebuilds the chrome that `seedFaderChrome` created — seeding is only useful pre-boot behind the overlay; remove one of them.
- Waveform worker is created with absolute `/js/waveform-worker.js` (and SW at `/sw.js`, manifest `/`): breaks under subpath hosting; derive from `import.meta.url`.
- `loadURL` has no timeout/progress; large fetches look frozen — stream to a progress toast.
- `alert("Couldn't start audio…")` on boot failure — replace with a styled dialog including the actual capability hint (worklet unsupported vs. autoplay).
- Practice-mode BPM slider undo: `pushState` on `pointerdown` only; keyboard changes to the slider skip undo.
- FFT visualizers draw every frame even when their canvases are `display:none` in the controller-center; also fixed 145×34 attribute size = blurry on retina. Skip when hidden; scale by DPR.
- Meta/OG tags absent — add description, `og:title/image` (use icon-512) for link sharing; premium products have good unfurls.
- Help dialog drifts from reality (stack view gone, relabeled transport, no mention of FX/sampler/loop-to-pad). Generate the keyboard section from `config.keys` so it can't drift.

**Phase S1 — sound-fidelity engine (2026-07-23):** ✅ **IMPLEMENTED**
A dedicated DSP module (`js/synth.js`) replaced the inline oscillator voices in `songbuilder.js`:
- **Mastering:** the offline render's default-settings DynamicsCompressor (−24 dB/12:1 — the single biggest "amateur sound" cause) is now a gentle 2.5:1 glue compressor plus a pure-JS post-render pass (`masterFinalize`): windowed loudness normalization toward a target RMS and a look-ahead brickwall limiter (same algorithm as the live `limiter-processor` worklet), so renders come out consistent and un-squashed.
- **Voices:** every patch rebuilt on a real architecture — exponential ADSR with release tails that ring past the note end, detuned unison with stereo spread (pads ×4, strings ×5, leads ×3), filter envelopes + key tracking, velocity → level/brightness. FM tine e-piano (mod ratio 14 + body overtone), 9-drawbar organ (key click, 6.9 Hz vibrato, 3rd-harmonic percussion), Karplus-Strong guitars/upright with brightness-shaped excitation, pick-position comb, body EQ and pick transients.
- **Drums v2:** analog-style hits synthesized to cached buffers with pure JS (deterministic, Node-tested, 2 nodes per hit): layered kicks (click + swept body + tanh drive), dual-partial + snappy-noise snares, 6-oscillator metallic hat/cymbal banks (808 ratios), real bossa rim-shot, per-kit tuning incl. lo-fi bitcrush.
- **FX v2:** reverb IRs with pre-delay, early reflections and progressively damped tails (replaces white-noise bursts, PAD sends + deck BeatFX); tempo-synced dotted-8th ping-pong echo with darkening feedback (PAD) and BPM-synced, feedback-filtered deck echo that follows load/detect/SYNC/tempo (`Deck.setBpm`/`BeatFX.setBpm`); stereo ensemble chorus baked into pad/strings/e-piano/organ/lead buses.
- **Musicality:** deterministic humanized velocity on all lanes (downbeat lean, offbeat sit-back, seeded ±4% jitter — same song always renders identically), drum-lane micro-dynamics, brighter track tone-control curve, GM sample releases no longer amputated at 160 ms.
- Tests: `test/synth.test.js` (pure-DSP; 23/23 with theory). SW cache → v9. Not in S1 (next): the user-facing synth editor panel (S2), curated self-hosted sample sets (S3).

**Phase S2 — the synthesizer editor (2026-07-24):** ✅ **IMPLEMENTED**
Patches became **data instead of code**. Each of the 14 factory sounds is now an engine id plus a parameter set (`FACTORY_PATCHES` in `js/synth.js`), rendered by one of four parameter-driven engines — **subtractive** (2 osc + sub + noise → filter w/ env, LFO, key-follow → ADSR, unison, vibrato, transient), **fm** (2-op w/ index envelope + overtone), **organ** (9 drawbars + percussion + key click + vibrato), **pluck** (Karplus–Strong w/ brightness, damping, pick, body thump, strum). `ENGINE_SCHEMA` declares every editable parameter with range/step/unit, and `resolvePatch()` merges factory ⊕ song overrides with full clamping (junk, NaN, unknown keys and engine-spoofing are all rejected).
- **The editor:** a schema-driven accordion in the PAD inspector — Analog exposes 33 controls, Drawbar 21, FM 15, String 13. It rebuilds itself from the schema, so adding a parameter to `synth.js` automatically gives it a control. Live audition on every change, per-parameter "edited" dots, an EDITED badge, Reset-patch, and Apply-to-all-matching-sections.
- **Storage:** overrides live in `section.patches['<lane>:<sound>']` and are **sparse** — only what the user actually changed (one edit = ~30 bytes), and an edit back to the factory value deletes itself. Living inside the section object means patches inherit undo/redo, autosave, project slots, JSON import/export and render-cache invalidation for free; a song with no `patches` key renders exactly as it did before the editor existed.
- **The last fake element is gone:** `.inspector-wave`'s decorative bar row (flagged in §4.8) is now a real offline render of the selected patch, redrawn as you edit.
- Verified: 31/31 tests; all 14 factory patches measured against the S1 baseline — single-voice patches within 1% and the only deliberate deltas are the S1 review fixes; UI round trip (edit → sparse store → audible change → undo → redo → reset) driven through the real DOM. SW cache → v10.

**Phase S3 — self-hosted sample fidelity (2026-07-24):** ✅ **IMPLEMENTED**
The Sampled·GM engine no longer depends on a third-party CDN at release time:
- **Self-hosting:** `npm run samples` (`scripts/fetch-samples.js`) downloads the 14 FluidR3_GM programs the app uses (~32 MB, MIT — attribution in `samples/README.md`) into `samples/FluidR3_GM/`, keeping the upstream one-file-per-instrument format so the loader is unchanged. `instruments.js` loads same-origin first (relative URL, subpath-safe) and falls back to the gleitz CDN per file on 404/failure. The service worker's on-demand cache makes each instrument work **offline after first use** (cross-origin CDN responses were never cacheable); `build.js` ships `samples/` in dist (optional, warns if absent) and firebase serves them immutable. Drum one-shots stay CDN-fetched by the browser (their recording licenses are unclear — not redistributed; the S1 synth kits are the asset-free default).
- **Playback quality:** the fixed ×2.2 makeup gain is replaced by per-sample **measured-peak normalization** (every program lands at the synth voices' level; verified peaks 0.09–0.16 across five differently-mastered programs, boost clamped ×6); velocity now darkens soft hits through a low-pass; and a decaying-instrument set (e-piano, celesta, guitars, basses) **rings past the note end** with a slow fade instead of being gated (verified: e-piano tail audible 0.5 s after note end, sustained programs gate silently) — the gate was the last thing making real samples sound synthetic.
